# Обская губа — веб-карта

Стартовый стек для регулярно обновляемой карты: PostgreSQL/PostGIS хранит объекты, GeoServer публикует их как WMS/WFS, Leaflet показывает слои поверх OpenStreetMap. По умолчанию сборщик запрашивает объекты OpenStreetMap через Overpass API в области Обской губы.

## Запуск на сервере

Нужны Docker и Docker Compose. Веб-карта слушает порт `8080`; GeoServer доступен на `127.0.0.1:8081` только локально, чтобы его панель администратора не оказалась открытой в интернет. Для внешнего доступа настройте HTTPS reverse proxy и задайте `PUBLIC_BASE_URL` в `.env`.

```sh
cp .env.example .env
# задайте пароли в .env
docker compose up -d --build
```

Карта: `http://<хост>:8080`

GeoServer на сервере: `http://127.0.0.1:8081/geoserver` (для доступа извне используйте SSH-туннель или защищённый reverse proxy).

Слой: `obsbay:map_features` (WMS/WFS)

Первый запрос сборщик выполняет при старте, затем повторяет с интервалом `POLL_INTERVAL_SECONDS` (по умолчанию 6 часов). Принудительно запустить сбор можно командой:

```sh
docker compose run --rm poller python -m app.poller
```

## Область и состав данных

Область по умолчанию задана bbox `68.0,66.0,74.5,74.0` (юг, запад, север, восток), покрывающим Обскую губу с прилегающей территорией. Для изменения области задайте `BBOX_SOUTH`, `BBOX_WEST`, `BBOX_NORTH`, `BBOX_EAST` в `.env`.

Начальный Overpass-запрос собирает объекты с тегами `man_made`, `industrial`, `landuse`, `natural`, `waterway`, `seamark`, `public_transport` и `amenity`. Состав можно менять в `config/overpass.ql`. Данные OSM не являются непрерывным мониторингом: Overpass возвращает картографические объекты, обновляемые участниками OpenStreetMap. Для метео, ледовой обстановки, судов, промысловых/производственных датчиков или других предметных данных потребуется указать источник/API и его условия доступа; адаптер импорта можно подключить к той же таблице PostGIS.

Таблица хранит последний полученный снимок. При успешном импорте отсутствующие в новом ответе OSM объекты удаляются из таблицы. При ошибке запроса прежние данные сохраняются.

## Настройки

Скопируйте `.env.example` в `.env` и замените пароли перед публикацией. Остальные основные настройки:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `POLL_INTERVAL_SECONDS` | `21600` | Интервал обновления |
| `OVERPASS_URL` | `https://overpass-api.de/api/interpreter` | Overpass endpoint |
| `OVERPASS_QUERY_FILE` | `/app/config/overpass.ql` | Файл запроса |
| `GEOSERVER_ADMIN_USER` | `admin` | Пользователь GeoServer |
| `GEOSERVER_ADMIN_PASSWORD` | задаётся в `.env` | Пароль GeoServer |

Используйте публичные тайлы OSM с соблюдением [политики использования](https://operations.osmfoundation.org/policies/tiles/). Для высокой нагрузки подключите отдельный tile-сервер или коммерческого поставщика тайлов.

## Личный кабинет (демо)

Сайт статический (папка `web/`, все пути относительные — подходит для GitHub Pages). Карта открыта всем, кабинет — после входа (`login.html`). На странице входа есть «Войти как гость» — для показа: гость видит кабинет как администратор, но ничего не меняет, отдел выбирает сам. Авторизация демонстрационная, без сервера: пользователи, роли и сессия хранятся в `localStorage` браузера (`web/auth.js`), поэтому регистрации видны только в том браузере, где они сделаны. Для общей базы пользователей `auth.js` нужно заменить сервером или облачной БД с тем же интерфейсом `window.Auth`.

Стартовый администратор: `1cem1nt` / `1cem1nt`. Новые пользователи регистрируются сами и получают статус «Ожидает подтверждения» — им доступны только профиль и смена пароля. В разделе «Пользователи» все показаны по отделам; администратор назначает отдел и роль:

| Роль | Доступ |
| --- | --- |
| Администратор | новости, кабинет отдела, сотрудники, все пользователи — менять любых |
| Администратор отдела | новости, кабинет отдела, сотрудники, все пользователи — менять только людей своего отдела (кроме перевода в другой отдел и назначения администраторов) |
| Руководитель отдела | новости, кабинет отдела, сотрудники отдела |
| Сотрудник | новости, кабинет отдела |
| Ожидает подтверждения | профиль |
| Гость | как администратор, но только просмотр |

Новости демо-режима (`web/news.js`) тоже хранятся в `localStorage`: другие отделы публикуют их в разделе «Новости», КМНС видит их плитками.

«Забыли пароль?» в демо-режиме меняет пароль сразу по существующему логину. Роли, отделы и наполнение кабинетов задаются в `web/auth.js`.
